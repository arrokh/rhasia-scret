# Code of Conduct

## Our standard

We want rhasia-scret to be a welcoming, technically rigorous project. People
participating in issues, discussions, reviews, documentation, code, releases,
and support must:

- be respectful and assume good faith while still addressing evidence;
- use inclusive, professional language and welcome different experience levels;
- give actionable feedback about the work rather than attacking a person;
- protect user privacy and never request or disclose secrets, Vault content,
  credentials, or private security-report details in public channels; and
- accept maintainer decisions, review constraints, and temporary security
  embargoes once the rationale is documented.

Unacceptable behavior includes harassment, discrimination, threats, personal
attacks, deliberate exposure of private data, credential or secret hunting,
publishing an embargoed vulnerability, impersonation, spam, and sustained
disruption of project operations.

## Enforcement

Report a conduct concern privately to the repository maintainer through the
security contact in [`SECURITY.md`](SECURITY.md) or the project owner's
private GitHub contact. Do not open a public issue with personal or sensitive
details. The maintainer may remove content, pause participation, request a
correction, restrict access, or escalate to the appropriate platform or legal
authority. Retaliation against a good-faith report is not permitted.

Reports are handled confidentially where possible. A reporter should include
the relevant project surface, approximate dates, links or redacted evidence,
and the outcome they need; never include credentials, Vault content, OTPs,
cookies, tokens, or private vulnerability details in a public channel.

This policy is adapted for the project from the Contributor Covenant approach;
the project may revise it through the governance process.
