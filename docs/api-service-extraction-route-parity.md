# API extraction route parity manifest

**Status:** Normative plan artifact — implementation and issue creation remain blocked until this manifest and the extraction plan are approved.

This manifest is the row-level companion to [`api-service-extraction-plan.md`](api-service-extraction-plan.md). It records every target business operation: the 54 existing operations plus `GET /api/v1/personal-vault/destructive-reset`. Hono-derived `HEAD` behavior is tested separately and is not an additional business operation.

**Version rule:** each existing source route `/api/<path>` maps to exactly one public target route `/api/v1/<path>`. `/api` remains the namespace; `v1` is a fixed version segment. The proxy, SSR gateway, web/mobile clients, Worker, and Bun adapter must use `/api/v1/**`; no unversioned `/api/**` compatibility alias is implemented.

Every implementation row must additionally link to the source route and existing or newly relocated tests. The implementation may not change the listed authentication policy, response contract, encrypted encoding, transaction boundary, or invariant without an approved plan revision.

## Source and test anchors

- A non-dynamic source row maps to `apps/web/src/app/api/<path>/route.ts`; `:vaultId` and `:userId` map to `[vaultId]` and `[userId]`. The shared-vault audit `GET` row maps to the re-exported implementation in `apps/web/src/app/api/vaults/[vaultId]/audit-events/route.ts`; its `POST` row maps to `apps/web/src/app/api/shared-vaults/[vaultId]/audit-events/route.ts`.
- Existing route-contract anchors are `apps/web/src/tests/contract/{passwordless-auth-routes,passwordless-request-route,health-route,me-route,offline-sync-bundle-route,personal-accounts-route,personal-vault-destructive-reset-route,personal-vault-initialization-route,personal-vault-route,retention-purge-route,shared-vaults-route,time-route,user-crypto-profile-rewrap-route,user-encryption-identity-route,vault-archive-export-route,vault-imports-route}.test.ts` plus `logout-route.test.ts`, `oidc-auth-routes.test.ts`, and `proxy.test.ts`.
- Row anchors are: rows 1–9 use the passwordless, health, time, retention, `me`, logout, and proxy contract suites; rows 10–15 use `apps/web/src/tests/unit/identity/passkey-recovery-*-route.test.ts`; rows 16–23 use the personal-vault, initialization, destructive-reset, user-crypto-profile, user-encryption-identity, and vault-import contract suites; rows 24–46 use `shared-vaults-route.test.ts` plus the membership/secure-share unit route suites; rows 47–55 use `personal-accounts-route.test.ts`, `vault-archive-export-route.test.ts`, `offline-sync-bundle-route.test.ts`, and the audit/account unit route suites. Any row without a one-to-one existing contract test gets a new API contract test before that row is marked complete.
- Existing integration anchors are the `apps/web/src/tests/integration/prisma-*.test.ts` suites. Existing browser anchors are `apps/web/src/tests/browser/*.spec.ts`, especially encrypted vault workflows, offline PWA, archive import/export, security headers, navigation, and smoke coverage. These tests move with the behavior to API-owned test projects or become web-proxy/native transport tests as appropriate.
- The implementation must replace every web-specific anchor that directly imports Prisma or route modules, not merely copy the files.

## Mandatory review gates

- The source-route mapping, exact status/body/error contract, request schema, response schema, rate-limit policy, repository transaction, and existing test references must be filled for every row before child issues are created.
- Browser proxy, direct native bearer, SSR gateway, and where applicable Bun/Worker transports must be recorded separately; passing a direct Worker test alone does not establish parity.
- Every mutation must have a concurrency/idempotency result and a permitted read-after-write or explicit reason why no read exists.
- Every upload/download row must record byte limits, streaming behavior, cache policy, and client-only plaintext/key handling.
- Every delete/reset/purge row must record affected rows, deadlines, restoration behavior, and audit retention.
