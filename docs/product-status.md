## Support matrix

“Supported” describes the repository's current product implementation and documented behavior. Operators remain responsible for provider configuration, deployment security, backups, and availability.

| Capability                       | Status                       | Scope and limits                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| -------------------------------- | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Client                           | Supported                    | Responsive web application/PWA is the sole supported client. Installing the PWA is optional; there is no separately supported native Android or iOS application.                                                                                                                                                                                                                                                                                                |
| Browsers                         | Supported                    | The documented baseline is current and previous major Chrome, Edge, Firefox, and Safari releases with the required APIs ([ADR-0018](adr/0018-supported-pwa-browser-baseline.md)); hosted browser automation covers Chromium only, so Firefox/WebKit behavior has no required cross-engine test signal. Private browsing and embedded webviews are unsupported for remembered unlock and offline storage; see [browser acceptance](browser-acceptance-tests.md). |
| Local Profile and Local Vault    | Supported                    | Browser-owned encrypted data; no sign-in, server synchronization, or remote recovery. Losing browser storage loses the data unless a separate archive and key were saved.                                                                                                                                                                                                                                                                                       |
| Hosted authentication            | Supported                    | Passwordless email-link authentication is the only hosted authentication method. `AUTH_BACKEND=none` disables application sign-in and hosted APIs. Self-hosted Tailscale Serve/Funnel can be combined with either backend; Funnel is public, while passwordless still protects hosted features.                                                                                                                                                                 |
| Personal Vault                   | Supported                    | One encrypted Personal Vault per hosted Application User. The server stores encrypted content and permitted lifecycle/authorization metadata, not decrypted account content.                                                                                                                                                                                                                                                                                    |
| Shared Vault                     | Supported                    | Owners manage the Vault and membership. Members may receive independent add, edit, and soft-delete account permissions; restore, membership administration, Vault administration, and audit history remain owner-only.                                                                                                                                                                                                                                          |
| Offline hosted access            | Supported, limited           | Read-only encrypted snapshots contain Personal Vault data only. Shared Vaults are online-only. Offline changes are blocked and never queued for later replay.                                                                                                                                                                                                                                                                                                   |
| Encrypted Vault Archives         | Supported                    | Client-encrypted archives work with Local Vaults and hosted Vaults. Hosted export is owner-only; a member may import into an existing Shared Vault only with effective add-account permission. The separate archive key is required for import.                                                                                                                                                                                                                 |
| Passkey-Assisted Unlock/Recovery | Supported, browser-dependent | Optional online WebAuthn/PRF flows require a compatible browser/authenticator and server-verified assertion. They do not recover a Vault Unlock Secret on the server or replace hosted email-link authentication.                                                                                                                                                                                                                                               |

Rotation is not scheduled and cannot erase keys, ciphertext, or TOTP secrets already copied by a member or device.                                                                                                                                                                                      |

## Security and operational limits

- The server is designed to be honest-but-curious: it enforces authorization and stores permitted metadata and ciphertext, but it is not trusted with plaintext TOTP content or client-held keys.
- This model does not protect users if a malicious host or compromised web-client supply chain serves altered code, or if the browser/device is compromised. Ciphertext sizes, timing, and permitted authorization/lifecycle metadata are visible to the server.
- Revocation prevents future authorized online access; it cannot erase secrets or ciphertext already copied by a member or device.
- Local Vaults have no server recovery. Hosted offline snapshots are Personal-only and read-only.
- A self-hosted operator owns TLS, secrets, email delivery, database backups, retention scheduling, upgrades, and incident response. Repository tests do not verify those operational controls.
- The project has no formal independent security certification or audit. Review the [threat model](adr/0004-honest-but-curious-server-threat-model.md), [private vulnerability-reporting policy](../SECURITY.md), and deployment checklist before use.

For setup, start with the [self-hosting guide](self-hosting.md). For help, see [support channels](support.md).
