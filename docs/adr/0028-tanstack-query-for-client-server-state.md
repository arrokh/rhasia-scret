# TanStack Query for client server-state coordination

Client-rendered remote reads and writes use TanStack Query for request lifecycle state, retry policy, and stable operation keys. A root-scoped Query Client is created per browser session and is not persisted. Presentation components call cohesive context-owned hooks under `presentation/hooks`; HTTP details and context-specific error mapping live in context infrastructure clients. Identical transport, JSON serialization, and response handling are centralized in the shared `BrowserApiClient` class without moving endpoint semantics across bounded contexts.

Plaintext TOTP secrets, raw QR data, generated OTPs, Vault Encryption Keys, User Root Keys, Vault Unlock Secrets, private encryption keys, and decrypted Vault content must not be used as TanStack Query keys, mutation variables, cached query/mutation results, or mutation-function closures retained by the mutation cache. Cryptographic unlock, decryption, and passkey-recovery workflows therefore remain direct client-only operations coordinated by TanStack Form and context infrastructure; temporary recovery key bytes are explicitly cleared. Only permitted server state, opaque encrypted payloads, identifiers, static destructive-confirmation text, and non-sensitive time metadata enter TanStack Query state.
