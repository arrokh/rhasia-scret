## Scope and assumptions

The audit covers the Next.js App Router application, browser cryptography and TOTP runtime, Supabase SSR/session integration, Prisma data access and migrations, API routes, Local Vault/Local Vault Snapshot boundaries, archives/recovery/sharing, service worker/PWA behavior, CI/dependencies, localization/accessibility, performance instrumentation, tests, and operational documentation.

The server is reviewed as honest-but-curious. Plaintext TOTP secrets, QR data, OTPs, Vault Unlock Secrets, User Root Keys, Vault Encryption Keys, private encryption keys, and decrypted Vault content must remain client-only. Production Supabase, PostgreSQL, Vercel, DNS, deployment, backup, alerting, and organization settings were not available to this repository audit; absence of repository evidence is not a Pass.

Fixtures are deterministic or synthetic. No production Vault, account, session, archive, key, or secret was used. The audited checkout uses the repository's mise Node 24 configuration and pnpm 11.17.0; CI declares Node 26.5.0, so CI/runtime compatibility remains an operator release check.

## Executive result

**Release status: BLOCKED.** The repository has strong client/server separation, encrypted ciphertext contracts, authorization-focused Prisma adapters, redacted audit events, atomic retention paths, architecture tests, and a broad deterministic test suite. It does not yet establish authenticated cryptographic context for persisted payloads, provider-neutral authentication, or a tested production browser-delivery/security-header baseline. Those are High release blockers and are tracked by existing actionable issues #75, #76, and #77 rather than duplicated as new issues.

No Critical finding was confirmed from repository evidence. High findings remain open and block release until their linked remediation issues are implemented, independently reviewed, and validated.

## Zero-knowledge data-flow trace

- **QR/manual input:** parsed in browser memory; supported TOTP is normalized and raw URI/QR data is not a server contract.
- **Plaintext session:** decrypted account labels/configuration/secrets and generated OTPs exist only in active browser memory; lock paths clear mutable byte buffers as far as JavaScript permits.
- **Encryption:** AES-GCM payloads, P-256 ECDH/HKDF key wraps, Argon2id unlock derivation, passkey PRF packages, archives, and offline snapshots store opaque ciphertext. The missing semantic AAD binding is AUD-001.
- **Transport/persistence:** API routes receive opaque identifiers, versions, revisions, and ciphertext; Prisma stores encrypted blobs and permitted authorization/lifecycle metadata. Browser persistence uses encrypted snapshots/local records and static service-worker assets, not API/auth responses.
- **Synchronization/offline:** server-derived snapshots are read-only and are atomically replaced only after authorized bundle validation/decryption. Device-only Local Vault is independent and writable offline.
- **Archive/recovery/sharing:** archive keys, recovery wrapping keys, User Root Keys, and usable Vault Encryption Keys stay client-side; server-held packages are opaque. Archive/recovery/share route review remains tied to AUD-001/#75 and delivery/session controls to #76/#77.
- **Logging/audit/deletion:** redacted audit events use opaque IDs and permitted email metadata; no account names, OTPs, TOTP configuration, keys, or content should be logged. Retention purge and destructive reset are tested; client/device backups and already-obtained plaintext cannot be remotely erased.
