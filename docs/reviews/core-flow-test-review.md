These were gaps in specific inspected assertions, not evidence that the implementation was broken. They are addressed at unit level, not as new browser matrices.

| A1  | High     | Supported algorithms are SHA-1/SHA-256/SHA-512 in `packages/client-vault-core/src/modules/otp-runtime/domain/totp-configuration.ts`; `otp-runtime/browser-hmac-generator.test.ts` and `crypto/platform-protocol-vectors.test.ts` only assert SHA-1 known answers. Broader workspace zeroing tests already exist.                                             | Mutating a returned key must not alter the stored key; replacing one Vault key must preserve another Vault; repeated lock/logout must be safe. ## Implementation and verification

- **Smoke:** explicit 13-file allowlist, 33 Chromium tests (baseline: 100). Gate inventory now checks `.spec.ts` and `.spec.mts`, including the self-hosted configuration wizard. No remaining browser spec is silently left outside a gate.
- **Pruning:** removed decorative loading/landing layout, input-matrix, journey-boundary, and 3D continuity specs and the Button token-class unit test. The retained landing fallback checks keyboard navigation into Local Vault after model failures. Mixed browser tests retain touch filtering/reordering, search privacy, destructive confirmation, archive confirmation/failure safety, and real-stack encryption/authorization assertions.
- **A1:** retained SHA-1 and added SHA-256/SHA-512 independent RFC 6238 known-answer matrices in `otp-runtime/browser-hmac-generator.test.ts`.
- **A2:** added `packages/client-vault-core/tests/generate-totp.test.ts` for counter-byte carry and expiry at a 45-second boundary, invalid/negative time, and short HMAC output.
- **A3:** expanded `crypto/unlocked-vault-session.test.ts` for returned-copy mutation, key replacement with another Vault unaffected, and repeated cleanup.
- **A4:** expanded `vault-archive/browser-vault-archive-workflow.test.ts` to retain opened secret-buffer references and verify zeroing, empty accounts, repeated/null cleanup, and fixture isolation.
- **Preserved gates:** real-stack E2E has 8 tests and offline/PWA has 13. Navigation performance, workflows, check names, branch protection, and product code are unchanged.
- **Historical passing local verification before API-oracle retirement:** `env -u CI VITEST_MAX_WORKERS=2 PLAYWRIGHT_WORKERS=1 mise exec -- pnpm run test:full` passed using its own disposable PostgreSQL 16 Testcontainer. Core: 87 tests; TypeScript API: 420; API contract/client: 3/2; web: 648; browser smoke/E2E/PWA: 33/8/13. Separate root lint, typecheck, `pnpm test` (disposable container), architecture, and build commands also passed. These are prior gate counts only; fresh verification after retiring the oracle is still required.
- **Timing observation:** the passing browser gate stages took 52.5s smoke, 79.1s E2E, and 15.4s PWA. These are one local run, not a controlled before/after speedup or a forecast of hosted CI: worker counts and machine load differ.
- **Independent review:** identified two accidentally weakened search checks. Restored exact URL assertions while querying/after clearing/after reload and moved network/console privacy inspection after reload. Restored accessible-name assertions for the icon-only search toggle in both locales and open/closed states. These are functional privacy/accessibility guarantees, not cosmetic copy tests.
- **Earlier failures:** broad-suite browser readiness and API integration timeouts, followed by one disposable-container connection termination, occurred before this passing gate. No timeout was increased and no safety test was skipped to obtain success. Bounded worker counts were local invocation settings, not a checked-in reduction of CI coverage.
