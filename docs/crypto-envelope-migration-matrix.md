# Context-bound envelope migration matrix

This is the source-trace inventory for encrypted payloads in PR #239. The envelope version is the first ciphertext byte. Database/API fields such as `encryptionVersion`, `keyVersion`, account `revision`, and key-wrap JSON `version` are separate metadata and do not prove the inner ciphertext is v2.

## Production context-free v1 decrypt sites

The remaining context-free `decryptPayload` calls are confined to explicit migration or unlock operations:

1. `packages/client-vault-core/src/modules/crypto/application/unlock-personal-vault.ts` — legacy profile wrappers inside passphrase/User Root Key unlock; validates recovered key lengths and returns v2 replacements for persistence.
2. `packages/client-vault-core/src/modules/crypto/application/encrypted-payload-migration.ts` — generic explicit v1 migration primitive; callers must supply a payload-specific validator and persistence store.
3. `packages/client-vault-core/src/modules/vault-membership/application/shared-vault-key-wrap-migration.ts` — explicit legacy Shared Vault key-wrap conversion.
4. `packages/client-vault-core/src/modules/crypto/application/user-encryption-key-rotation.ts` — explicit legacy member-key conversion while rotating the User Encryption Key Pair.
5. `packages/client-vault-core/src/modules/crypto/application/vault-key-rotation.ts` — explicit validated name/account conversion during Shared Vault key rotation.
6. `apps/web/src/modules/local-vault/application/local-vault-workflow.ts` — explicit Local Vault migration only; ordinary unlock blocks v1.

`account-payload.ts`, workspace normal reads, and `unlock-shared-vault.ts` reject legacy envelopes rather than falling back to context-free decryption. The explicit calls above are not ordinary-reader compatibility branches.

## Verification status

Online browser journeys cover both profile wrappers; the all-payload workspace journey retrieves synthetic v1 Personal/Shared names, Personal/Shared account configurations, and a Shared member key, validates and persists ciphertext replacements, then loads the workspace again from v2. A separate browser offline journey migrates profile wrappers, Personal name, and Personal account data in the encrypted local snapshot, preserves wrong-passphrase inputs, and reopens from v2. Mobile workspace coverage and focused unit/API-route tests are present. The API Prisma integration suite passed via the inspected disposable PostgreSQL Testcontainers route (22 files / 64 tests). The Chromium browser gate passed sequentially: 41 smoke tests, 8 end-to-end tests, and 5 offline-PWA tests. The full repository gate remains incomplete: web route-bundle enforcement fails for `/vaults` at 751,754 raw / 226,574 gzip bytes against the 750,000 / 225,000 budgets, which aborts that command before its browser stage. Run a fresh full gate after resolving the bundle regression; real-device verification remains separate.
