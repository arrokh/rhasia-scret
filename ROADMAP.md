legal, deployment, privacy, and release evidence can hold a milestone even
when implementation code is complete.

## Priorities

Security and dependency blockers, documented provider responsibility, and
reproducible release evidence take priority over feature expansion. The
[MVP plan](docs/mvp-plan.md) and architecture/security ADRs remain the source
of truth for product scope and technical boundaries.

## How to propose a change

Open a focused issue or pull request using the public templates. Explain the
user or operator outcome, affected bounded context, security and localization
impact, and verification evidence. Roadmap status changes require a linked
issue or merged change; release status requires the governance approval path.
